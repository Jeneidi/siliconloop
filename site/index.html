A2 agentic workflow for chip design

Code is not done until silicon says pass.

SiliconLoop asks an LLM to write Verilog, then lets an Icarus Verilog testbench decide whether the circuit actually works.

The problem

Looks right is not a verification result.

LLM-generated RTL can be syntactically plausible while still producing the wrong signal. SiliconLoop keeps the model away from the reference solution and gives it only the English spec, then the simulator verdict.

That same black-box discipline fits neural networks on edge devices, PyTorch signal processing, wafer yield analytics, SQL-backed workflows, and agentic AI systems built around an LLM or LangChain.

What it does

A compiler-and-testbench feedback loop.

For every problem, Python writes the candidate into a temporary folder, compiles it with Icarus Verilog 13.0, runs the official testbench, and records pass, wrong output, compile error, or timeout.

The site replays recorded evidence with no API key. The full implementation, cached model responses, and tests are in the repository.

The method

The model proposes. The testbench decides.

The experiment keeps the LLM step narrow and makes the executable verification mechanism visible. It is Python orchestration around a real simulator, not a screenshot of a promising answer.

  1. Load the official specs

    Use the NVlabs VerilogEval spec-to-RTL prompts, references, and testbenches under the MIT license.

  2. Generate one RTL module

    Claude Haiku 5.5 sees the English problem and returns one standalone TopModule.

  3. Run the black-box judge

    Icarus Verilog compiles and runs the untouched testbench with a 10-second timeout.

  4. Feed back simulator text

    On failure, the agent can use compiler output or mismatch text for up to 2 retries.

  5. Compare to the baseline

    Aggregate one-shot and looped pass rates, failure categories, retry fixes, calls, and latency.

No key required. This is a deterministic replay of recorded judge output.
