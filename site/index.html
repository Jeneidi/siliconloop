The problem

Code that looks right can still be wrong.

Every computer chip is designed in code before it is made. A bug found after the chips are made can cost millions. In 1994, a math bug in Intel's Pentium chip cost the company $475 million in replacements.

AI can now write this chip-design code, and the code often looks fine. Looking fine is not proof. SiliconLoop counts a design as working only when a machine runs it and every output matches the official answer.

module TopModule(output zero);
  assign zero = 1'b0;
endmodule

What it does

A tester, not a guess, has the final say.

For each problem, the tester builds the AI's design, runs it, and compares every output with the official answer. The AI never sees that answer.

Each try gets one of four results: passed, wrong output, did not build, or too slow. The demo below replays the real run, so it needs no AI account. All the code and saved AI answers are on GitHub.

How it works

The AI suggests. The tester decides.

The AI has one small job: write the design. Whether it works is decided by actually running it, not by reading the code and hoping.

  1. Start from a public test set

    Each problem has an English description of a circuit, an official answer, and an official test.

  2. The AI writes the code

    Claude reads only the English description and writes one design.

  3. The tester runs it

    The design is built and checked output by output. A run longer than 10 seconds counts as a fail.

  4. Errors go back to the AI

    If it fails, the AI gets the tester's error message and tries again, up to 2 more times.

  5. Compare with the first try

    The final score is set against the first-try score, so the gain from retrying is measured, not assumed.

Technical details

Spec-to-RTL generation with Claude Haiku 5.5 (claude-haiku-5-5) via the Claude Code CLI, recorded 2026-10-12, judged by Icarus Verilog 13.0. One-shot is the baseline; the agentic loop feeds simulator output back for up to 2 retries.

Limitations: 60 selected problems, not full-dataset performance; one model and one recorded run. The site replays recorded evidence and does not compile visitor RTL. Test gate: .venv/bin/python -m pytest -q.

  1. Dataset

    NVlabs VerilogEval dataset_spec-to-rtl (MIT license): 156 problems with prompts, reference modules, and testbenches. 155 pass an Icarus 13.0 compatibility sweep. Prob099 is excluded: its testbench references Y2 and Y4, while its reference module exposes Y1 and Y3.

  2. Selection

    The 60 hardest compatible problems, ranked before any model call by a metadata-only score: 100 × FSM indicator + 50 × sequential indicator + 10 × temporal/state keyword count + prompt lines + 0.5 × reference lines + 0.25 × testbench lines. Ties break on problem ID.

  3. Judge

    iverilog -g2012 compiles the candidate TopModule, reference, and untouched testbench in a temp folder; vvp runs it with a 10-second timeout. Pass only on Mismatches: 0. Statuses: pass, wrong_output, compile_error, timeout. The model never sees the reference module or testbench.

  4. Results

    One-shot 73.3% (44/60: 14 compile errors, 2 wrong outputs). Looped 98.3% (59/60); retries fixed 15. Prob149 stayed wrong_output after 2 retries. 78 LLM calls (60 one-shot + 18 retries), 0 cache hits, $0 direct API cost, 1,160 s total.
